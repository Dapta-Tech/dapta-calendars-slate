Product analytics never forwards a campaign tag that is not a label. New `analyticsCampaignValue` (and `CAMPAIGN_VALUE_MAX`): a `utm_*` value passes only if it is made of letters, marks, digits, the space, currency signs, emoji, dashes, typographic quotes, brackets and a short list of punctuation (an allowlist, checked after Unicode compatibility folding) and holds no invisible character outside an emoji, address, URL, path or IP address, colon not followed by a space, HTML entity, phone number (`+`-led, short digit blocks, or a national format), or encoding left twice; the exact rules are in its doc comment. An encoding left once is decoded and checked again, and the decoded label is sent. Date-coded names, slashed dates and joined ids are not read as phone numbers or paths. The API's `attribution_captured` event and account update send only the tags that pass, with `utm_withheld: true` on both when one was held back. `referrerDomain` answers only host names a browser can send. Host browser events also drop a search engine's keyword.
